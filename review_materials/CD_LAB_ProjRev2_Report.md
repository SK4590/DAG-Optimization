## 1. Problem Statement

Unoptimized intermediate code, such as standard Three-Address Code (TAC) generated by compiler frontends, frequently contains redundant computations, duplicate subexpressions, and dead operations. Values are repeatedly recomputed across a basic block, unnecessarily wasting CPU cycles, memory bandwidth, and execution time. Our goal is to build an optimizing compiler engine that constructs a Directed Acyclic Graph (DAG) for basic blocks to automatically detect, fold, simplify, and eliminate these redundancies while synthesizing valid, optimized TAC.

### Key Challenges Addressed in Review 2:
* **Constant-Time Redundancy Detection:** Eliminating duplicate calculations in $O(1)$ time without costly full-graph traversals.
* **Commutative Operations:** Recognizing semantic equivalence for commutative operations ($a + b \equiv b + a$, $x \times y \equiv y \times x$).
* **Variable Reassignment & Aliasing:** Handling Dragon Book node kill and label detachment when variables are overwritten.
* **Compile-Time Constant Evaluation:** Folding static arithmetic and propagating constant values through the graph.
* **Algebraic Reductions:** Identifying mathematical identities ($x+0$, $x \times 1$, $x \times 0$, $x-x$, $x/1$) for strength reduction.
* **Code Generation:** Reconstructing shortened, valid Three-Address Code and Graphviz visual representations from the DAG.

### Naive Input vs Optimized Output:

| :--- | :--- | :--- |

## 5. Local Optimizations Breakdown (Review 2 Comprehensive)

| Optimization Technique | Mechanism & Description | Before vs After Transformation |
| :--- | :--- | :--- |
| **Common Subexpression Elimination (CSE)** | Detects identical operations using signature hashing and reuses the existing primary variable. | `[Before]` `t1 = a * b; t2 = a * b`<br/>`[After]` `t1 = a * b; t2 = t1` |
| **Commutative Expression Matching** | Canonicalizes operands for commutative operators (`+`, `*`, `&`, `|`, `^`, `==`, `!=`) by ordering node IDs: `op(min, max)`. | `[Before]` `t1 = a + b; t2 = b + a`<br/>`[After]` `t1 = a + b; t2 = t1` |
| **Variable Reassignment & Node Kill** | Dragon Book rule: when a variable is reassigned, its label is detached from the old node, preventing stale aliasing. | `[Before]` `a = b+c; t1 = a-d; a = 10; t2 = a-d`<br/>`[After]` `a = b+c; t1 = a-d; a = 10; t2 = 10-d` |
| **Compile-Time Constant Folding** | Statically evaluates arithmetic on constant operands and creates a folded constant leaf node. | `[Before]` `t1 = 12 + 8; t2 = t1 * 2`<br/>`[After]` `t1 = 20; t2 = 40` |
| **Algebraic Identity Simplification** | Applies mathematical reduction rules: $x+0=x$, $x-0=x$, $x-x=0$, $x \times 1=x$, $x \times 0=0$, $x/1=x$, $x/x=1$. | `[Before]` `t3 = a * 1; t5 = c * 0; t6 = d - d`<br/>`[After]` `t3 = a; t5 = 0; t6 = 0` |
| **Redundant Leaf Prevention & Copy Propagation** | Reuses existing symbol table nodes for duplicate operands and propagates copy aliases directly. | `[Before]` `t1 = a + b; t2 = a - c; x = y`<br/>`[After]` Both share leaf `'a'`; `x` aliases `'y'` |

## 6. Core Mechanisms & Algorithms

### A. O(1) Value Numbering with Commutative Sorting
Instead of scanning previously processed instructions in $O(N^2)$ time, our `DAGOptimizer` computes a string signature for each operation:
$$\text{sig} = \text{op}(\min(\text{leftId}, \text{rightId}), \max(\text{leftId}, \text{rightId}))$$
If `isCommutative(op)` is true and `leftId > rightId`, the IDs are swapped. A hash map lookup (`valueNumbering[sig]`) verifies uniqueness in $O(1)$ average time.

### B. Dragon Book Node Kill & Label Detach Semantics
When variable $x$ is updated via an instruction:
1. `detachVariable(x)` checks if $x$ already exists in `varToNode`, removing $x$ from the previous node's active `labels` vector.
2. `attachVariable(x, targetNodeId)` attaches $x$ to the new node and updates `varToNode[x] = targetNodeId`. This ensures subsequent instructions reference the updated value.

### C. Chronological Replay Code Generation
The code generator replays each processed step in execution order. If an instruction created a new computation, it emits the operation with current active representative variables. If it matched an existing node (CSE), it emits a clean copy assignment (e.g., `t2 = t1`), perfectly preserving downstream variable dependencies.
